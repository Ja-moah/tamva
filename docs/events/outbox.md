# Transactional outbox

Domain state and `OutboxEvent` are written in the same `transaction.atomic()` block. `packages.events.tasks.dispatch_pending_outbox_events` (a Celery Beat task, `OUTBOX_DISPATCH_INTERVAL_SECONDS` apart, default 15s) locks unpublished rows with `select_for_update(skip_locked=True)`, so multiple workers never process the same row, and hands each to the appropriate domain consumer (currently `domains.notifications.services.process_outbox_event` for `case.*` events). Delivery is at least once: `process_outbox_event` is idempotent per `(event, template, channel, recipient)`, so a crash mid-batch and re-processing never duplicates a notification.

The contract carries `event_id`, `event_type`, `event_version`, `occurred_at`, `producer`, `tenant_id`, `correlation_id`, and `payload`. A failing event's `attempts`/`last_error` are recorded; after `MAX_ATTEMPTS` (5) it is dead-lettered — `published_at` is set so it stops being retried, but the row and its `last_error` stay queryable for operator investigation and manual replay, rather than retried forever or silently dropped. Event types the dispatcher does not recognize (`NOTIFICATION_EVENT_TYPES`) are left with `published_at` null rather than being marked handled. Events remain queryable for controlled replay, and incompatible payload changes require a new event version. Kafka is intentionally absent.
